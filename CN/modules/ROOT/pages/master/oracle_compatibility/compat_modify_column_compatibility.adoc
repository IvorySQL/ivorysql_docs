= MODIFY 列兼容

== 目的

IvorySQL 在 Oracle 兼容模式下支持通过 `ALTER TABLE ... MODIFY` 修改已有列的类型和可空性，兼容迁移脚本中常见的 `MODIFY (列名 类型 NOT NULL)` 写法。

== 功能说明

=== 语法

[source,sql]
----
ALTER TABLE table_name MODIFY column_definition;
ALTER TABLE table_name MODIFY (column_definition [, ...]);
----

其中，类型和可空性的列定义形式如下：

[source,text]
----
column_name data_type
column_name { NOT NULL | NULL }
column_name data_type { NOT NULL | NULL }
----

单列修改可省略括号；在同一个 MODIFY 子句中修改多列时，将列定义放在括号中并以逗号分隔。

[cols="2,3",options="header"]
|===
|修改方式 |行为
|仅指定类型 |修改列类型或长度，保留原有可空性
|`NOT NULL` |设置非空要求，并验证已有数据
|`NULL` |移除列的非空要求，不修改已有数据
|类型加 `NOT NULL` 或 `NULL` |在同一条 ALTER TABLE 语句中修改类型和可空性
|===

类型修改遵循底层 ALTER TABLE 的转换及依赖检查规则。增加字符列长度是常见用法；其他转换能否成功取决于原类型、目标类型、已有数据及相关约束，不能将接受语法等同于允许任意类型转换。

=== 保留的列属性语法

MODIFY 也保留已有的列可见性和 identity 属性修改入口：

[source,sql]
----
ALTER TABLE table_name MODIFY (column_name INVISIBLE);
ALTER TABLE table_name MODIFY column_name VISIBLE;
ALTER TABLE table_name MODIFY (column_name GENERATED ALWAYS AS IDENTITY);
ALTER TABLE table_name MODIFY (column_name GENERATED BY DEFAULT AS IDENTITY);
ALTER TABLE table_name MODIFY (column_name DROP IDENTITY);
----

identity 的生成方式修改用于已有 identity 列，仍需满足对应属性检查。更多可见性行为见 xref:master/oracle_compatibility/invisible_column.adoc[不可见列]。

== 使用示例

以下示例在 Oracle 兼容模式的 psql 会话中按顺序执行。包含预期错误的示例使用自动提交方式，避免错误使显式事务进入中止状态。

=== 修改类型并设置 NOT NULL

[source,sql]
----
CREATE TABLE modify_demo (a VARCHAR2(10), b VARCHAR2(10), c NUMBER);
INSERT INTO modify_demo VALUES (NULL, 'x', 1);

ALTER TABLE modify_demo MODIFY (a VARCHAR2(20) NOT NULL);
----

列 a 含有 NULL，修改失败，主要错误信息为：

[source,text]
----
ERROR:  column "a" of relation "modify_demo" contains null values
----

先处理已有 NULL，再重试；列 b 演示不带括号的写法。

[source,sql]
----
UPDATE modify_demo SET a = 'y';
ALTER TABLE modify_demo MODIFY (a VARCHAR2(20) NOT NULL);
ALTER TABLE modify_demo MODIFY b VARCHAR2(30) NOT NULL;
----

此后 a、b 均要求非空。失败的 ALTER TABLE 不会只保留其中的类型修改。

=== 单独调整可空性与批量修改

[source,sql]
----
ALTER TABLE modify_demo MODIFY (a NULL);
ALTER TABLE modify_demo MODIFY b NULL;
ALTER TABLE modify_demo MODIFY (a VARCHAR2(40) NOT NULL, c NUMBER NOT NULL);

INSERT INTO modify_demo VALUES ('012345678901234567890123456789', 'longer value', 2);
SELECT c, length(a) AS a_length FROM modify_demo ORDER BY c;
----

结果说明原有数据保留，扩容后的列可以保存更长的值：

[source,text]
----
 c | a_length
---+----------
 1 |        1
 2 |       30
(2 rows)
----

=== 仅修改类型保留可空性

[source,sql]
----
ALTER TABLE modify_demo MODIFY (c NUMBER(10));
ALTER TABLE modify_demo MODIFY b VARCHAR2(40);
\d modify_demo
----

此时 a 为 `varchar2(40) NOT NULL`，b 为可空的 `varchar2(40)`，c 为 `number(10,0) NOT NULL`。未写 NULL 或 NOT NULL 时，类型修改不会重置原有可空性。

[source,sql]
----
DROP TABLE modify_demo;
----

== 使用说明

* 执行者需具备修改目标表的权限；权限、锁和依赖检查沿用 ALTER TABLE 的处理。
* 设置 NOT NULL 前应清理已有 NULL；移除非空要求仍受主键等相关约束限制。
* 一条 MODIFY 可以展开成多个内部操作，但整条语句仍按事务规则处理；任一操作失败，整条语句的修改回滚。
* 类型修改或非空验证可能扫描或重写表，执行时间和锁影响取决于表大小、类型及约束。
