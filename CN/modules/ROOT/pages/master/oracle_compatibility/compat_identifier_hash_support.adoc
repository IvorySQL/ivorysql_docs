= 标识符支持 # 字符

== 目的

IvorySQL 在 Oracle 兼容模式下允许未加双引号的标识符包含 `#`，便于迁移使用 `STATISTIC#` 等名称的 Oracle SQL，减少为表名、列名补充双引号的改写。

== 功能说明

=== 标识符规则

`#` 可以出现在未加引号标识符的中间或末尾，不能作为首字符。原有首字符规则保持不变，例如可以使用英文字母或下划线开头。

[cols="2,3",options="header"]
|===
|示例 |说明
|`statistic#` |末尾包含 # 的列名
|`col#1`、`my#column` |中间包含 # 的列名
|`test#table` |包含 # 的表名
|`col_$#4` |组合使用下划线、$、# 和数字
|===

`$` 原本就允许出现在标识符的后续字符中，本功能增加的是 `#`。包含 `#` 不会改变名称的大小写处理和长度规则；引用标识符仍遵循既有的双引号及大小写转换规则，见 xref:master/oracle_compatibility/compat_case_conversion.adoc[引用标识符的大小写转换]。

=== 与运算符共存

`#` 仍可作为按位异或运算符，`#>`、`#>>`、`#-` 仍可作为 JSON 路径提取或删除运算符。词法分析会区分这些运算符与名称中的 `#`，支持 `jsonb#>>'{b}'` 等不带空格的写法。

以 `#` 结尾的标识符后若紧接 `>` 或 `-`，末尾的 `#` 会被识别为运算符的起始部分。比较和减法应写成 `statistic# > 0`、`statistic# - 1`，以空格明确边界。同样，`a#b` 是一个完整标识符；若需要对 a、b 做异或，应写成 `a # b`。

== 使用示例

以下示例在 Oracle 兼容模式的 psql 会话中执行。

=== 创建和查询包含 # 的列

[source,sql]
----
CREATE TABLE test_hash_ident (
    statistic# INT,
    col#1 INT,
    my#column INT
);
INSERT INTO test_hash_ident VALUES (1, 2, 3);
SELECT statistic#, col#1, my#column FROM test_hash_ident;
----

[source,text]
----
 statistic# | col#1 | my#column
------------+-------+-----------
          1 |     2 |         3
(1 row)
----

后续引用时无需因 # 字符添加双引号。比较和算术表达式中使用空格区分列名与运算符：

[source,sql]
----
SELECT statistic# - 1 AS previous_statistic
FROM test_hash_ident
WHERE statistic# > 0;
----

该查询返回一行，`previous_statistic` 为 0。

=== 创建包含 # 的表名和混合字符列名

[source,sql]
----
CREATE TABLE test#table (col_$#4 INT);
INSERT INTO test#table VALUES (100);
SELECT col_$#4 FROM test#table;
----

查询返回一行，`col_$#4` 为 100。建表、插入和查询均可直接使用这些名称。

=== 使用异或和 JSON 运算符

[source,sql]
----
SELECT 5 # 3 AS xor_result;
SELECT 5#3 AS xor_no_spaces;
SELECT B'1010' # B'1100' AS bit_xor;

SELECT '{"a":1}'::json#>'{a}' AS json_path_no_space;
SELECT '{"b":2}'::jsonb#>>'{b}' AS jsonb_path_no_space;
SELECT '{"a":1,"b":2}'::jsonb#-'{a}' AS jsonb_delete_no_space;
----

三个异或结果依次为 6、6、`0110`；JSON 运算结果依次为 JSON 值 `1`、文本 `2` 和 `{"b": 2}`。这些运算符不会因为允许标识符包含 # 而失去原有含义。

[source,sql]
----
DROP TABLE test#table;
DROP TABLE test_hash_ident;
----

== 使用说明

* 本功能针对 Oracle 兼容解析器中的标识符，不意味着 PostgreSQL 模式也接受相同的未加引号写法。
* 名称中的 # 属于标识符本身，引用对象时必须保留该字符。
* 名称以 # 结尾且与运算符相邻时，优先用空格明确边界，避免将列名的一部分解析为 JSON 运算符。
