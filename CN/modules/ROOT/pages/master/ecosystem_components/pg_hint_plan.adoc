= pg_hint_plan

== 概述

pg_hint_plan 是一个扩展，允许通过 SQL 注释中的 hints 来控制 PostgreSQL/IvorySQL 的执行计划。它能够在不修改 SQL 逻辑的情况下优化查询性能，在 PostgreSQL 和 Oracle 兼容模式下均可正常工作。


== 安装

[TIP]
源码安装环境为 Ubuntu 24.04(x86_64)，环境中已经安装了IvorySQL 5及以上版本，安装路径为/usr/ivory-5

=== 源码安装

[literal]
----
# 克隆 PG18 分支源码

git clone --branch PG18 https://github.com/ossc-db/pg_hint_plan.git
cd pg_hint_plan

# 编译安装插件
make PG_CONFIG=/usr/ivory-5/bin/pg_config
make PG_CONFIG=/usr/ivory-5/bin/pg_config install

----

=== 在 Windows 上从源码构建

[TIP]
本节在 Windows 11 上验证，编译器为 Visual Studio 2022 Build Tools（MSVC 19.44）。IvorySQL 的 Windows 移植仍在审查中，验证使用的 IvorySQL 是 https://github.com/jiabin777on-hue/IvorySQL/tree/win/reference[Windows 测试基线] 的提交 `947b50e1`，即 master 加上尚未合并的 Windows 移植 PR（IvorySQL #2321、#2332、#2333、#2485、#2530、#2811、#3418、#3419、#3420、#3421）。

在 “Developer PowerShell for VS 2022” 中编译并安装 IvorySQL。需要 Git、Strawberry Perl、winflexbison 和 Meson（含 Ninja）在 `PATH` 中。验证时另外加了 `-Dcassert=true -Dtap_tests=enabled` 以运行测试。

[source,powershell]
----
git clone --branch win/reference https://github.com/jiabin777on-hue/IvorySQL.git
Set-Location IvorySQL
git checkout 947b50e1
meson setup build --prefix=C:\ivorysql -Dauto_features=disabled -Duuid=none
ninja -C build
meson install -C build
Set-Location ..
----

Windows 上没有 PGXS，可以用 MSVC 的 `cl` 和 `link` 直接编译插件，并链接 IvorySQL 安装目录中的 `postgres.lib`。克隆时设置 `core.autocrlf=false`，避免测试数据文件被转换为 CRLF。

[source,powershell]
----
$IVY = 'C:\ivorysql'
$INC = "$IVY\include\postgresql\server"
$CFLAGS = @("/nologo", "/c", "/O2", "/MD", "/utf-8", "/std:c11", "/DWIN32", "/DWINDOWS",
    "/D__WINDOWS__", "/D__WIN32__", "/D_CRT_SECURE_NO_DEPRECATE", "/D_CRT_NONSTDC_NO_DEPRECATE",
    "/I.", "/I$INC\port\win32_msvc", "/I$INC\port\win32", "/I$INC", "/I$IVY\include")
git clone -c core.autocrlf=false https://github.com/ossc-db/pg_hint_plan.git
Set-Location pg_hint_plan
git checkout 52af48fb1ab4
win_flex --wincompat -o query_scan.c query_scan.l
cl @CFLAGS pg_hint_plan.c query_scan.c
link /nologo /DLL /OUT:pg_hint_plan.dll pg_hint_plan.obj query_scan.obj "$IVY\lib\postgres.lib"
Copy-Item pg_hint_plan.dll "$IVY\lib\postgresql\"
Copy-Item pg_hint_plan.control, pg_hint_plan--*.sql "$IVY\share\postgresql\extension\"
----

IvorySQL master 基于 PostgreSQL 19，所以验证使用 pg_hint_plan 的 master 分支（2.0.0，提交 `52af48fb1ab4`），而不是上面 IvorySQL 5 使用的 `PG18` 分支。源码不需要修改。`query_scan.c` 由 `query_scan.l` 生成，Windows 上用 winflexbison 提供的 `win_flex` 生成。

pg_hint_plan 需要预加载。IvorySQL 在 `ivorysql.conf` 中默认设置了 `shared_preload_libraries = 'gb18030_2022, liboracle_parser, ivorysql_ora'`，要把 pg_hint_plan **追加**到这个列表后面，例如 `shared_preload_libraries = 'gb18030_2022, liboracle_parser, ivorysql_ora, pg_hint_plan'`。如果只写 `'pg_hint_plan'`，会覆盖默认列表，Oracle 模式的连接会报 `liboracle_parser not found`。

验证结果：在 PG 模式下，插件自带的回归测试除 `hypopg`（需要另外安装 hypopg 插件）外共 19 个，通过 17 个。另外 2 个（`pg_hint_plan`、`ut-S`）的差异只在于表达式索引的自动命名：例如期望输出为 `p2_c1_val_120_idx`，实际为 `p2_c1_expr_idx`。这是 PostgreSQL 版本的差异，与 Windows 无关。

在 Oracle 模式下，扫描、连接、行数等 hint 的测试（`ut-J`、`ut-L`、`ut-G`、`ut-R`、`ut-fdw`、`hint_table`、`query_parser` 等）都通过。其余差异来自 Oracle 模式的语法和语义：不支持嵌套块注释；空字符串等同于 NULL；内置类型显示为 `pg_catalog.int4` 等形式。另外，`ut-init` 用到的 `CREATE EXTENSION btree_gist` 在 Oracle 模式下会失败，原因是不带字段限定的 `INTERVAL` 类型名（IvorySQL#1784）。插件自带的回归测试脚本按 PostgreSQL 的语法编写。Oracle 模式的 psql 要看到单独一行的 `/` 才会发送 `CREATE FUNCTION`（即使函数体用 `$$` 引用），所以要在 Oracle 模式下运行这些脚本，需要在每个 `CREATE FUNCTION` 语句后面加一行 `/`。

=== 修改数据库配置文件

修改 ivorysql.conf 文件，添加 pg_hint_plan 到 shared_preload_libraries：

[literal]
----
shared_preload_libraries = 'gb18030_2022, liboracle_parser, ivorysql_ora, pg_hint_plan'
----

重启数据库后配置生效。

=== 加载扩展

[literal]
----
postgres=# LOAD 'pg_hint_plan';
LOAD
----

== Hint 类型

pg_hint_plan 提供了多种类型的 hints 来控制查询执行计划的不同方面。

=== 扫描方法 Hints

指定表扫描方法的 hints：

* `SeqScan(table)` - 顺序扫描
* `IndexScan(table[ index])` - 索引扫描，可指定索引名
* `BitmapScan(table[ index])` - 位图扫描，可指定索引名
* `TidScan(table)` - TID 扫描

否定形式的 hints（禁止使用某种扫描方法）：

* `NoSeqScan(table)`
* `NoIndexScan(table)`
* `NoBitmapScan(table)`
* `NoTidScan(table)`

=== 连接方法 Hints

指定表连接方法的 hints：

* `HashJoin(table table[ table...])` - 哈希连接
* `NestedLoop(table table[ table...])` - 嵌套循环连接
* `MergeJoin(table table[ table...])` - 合并连接

否定形式的 hints：

* `NoHashJoin(table table)`
* `NoNestedLoop(table table)`
* `NoMergeJoin(table table)`

=== 连接顺序 Hints

* `Leading(table table[ table...])` - 指定连接顺序，表按顺序连接

=== 并行执行 Hints

* `Parallel(table count[ workers])` - 设置并行工作进程数量
    * `count` - 是否使用并行（0 表示不使用，1 表示使用）
    * `workers` - 并行工作进程数量（可选，默认值为规划器计算的值）

=== 其他 Hints

* `Set(enable_*)` - 设置 GUC 参数
* `Rows(table table[ table...] correction)` - 修正行数估计值

== 使用示例

=== 基本用法示例

使用 HashJoin 和 SeqScan hints：

[literal]
----
postgres=# /*+
   HashJoin(a b)
   SeqScan(a)
*/
EXPLAIN SELECT *
FROM pgbench_branches b
JOIN pgbench_accounts a ON b.bid = a.bid
ORDER BY a.aid;
----

=== 复杂多 Hint 示例

组合使用多个 hints 来控制复杂查询的执行计划：

[literal]
----
postgres=# /*+
   NestedLoop(t1 t2)
   IndexScan(t2 t2_pkey)
   MergeJoin(t1 t2 t3)
   Leading(t1 t2 t3)
*/
EXPLAIN SELECT * FROM table1 t1
JOIN table2 t2 ON t1.id = t2.id
JOIN table3 t3 ON t2.id = t3.id;
----

=== 并行执行示例

为多个表设置并行度和连接方法：

[literal]
----
postgres=# /*+
   Parallel(t1 3)
   Parallel(t2 5)
   HashJoin(t1 t2)
*/
EXPLAIN SELECT * FROM large_table1 t1
JOIN large_table2 t2 ON t1.id = t2.id;
----

=== 指定索引扫描示例

强制使用特定索引进行扫描：

[literal]
----
postgres=# /*+
   IndexScan(employees emp_name_idx)
*/
EXPLAIN SELECT * FROM employees
WHERE last_name = 'SMITH';
----

== Hint 表（可选功能）

pg_hint_plan 提供了一个可选的 hint 表功能，可以在表中持久化存储 hints。

=== 创建 Hint 表

[literal]
----
postgres=# CREATE TABLE hint_plan.hints (
    id serial PRIMARY KEY,
    norm_query_string text NOT NULL,
    application_name text,
    hints text NOT NULL,
    CONSTRAINT hint_plan_hints_norm_query_string_key UNIQUE (norm_query_string, application_name)
);
----

=== 插入 Hints

[literal]
----
postgres=# INSERT INTO hint_plan.hints (norm_query_string, application_name, hints)
VALUES (
    'SELECT * FROM table1 WHERE id = ?;',
    'psql',
    'SeqScan(table1)'
);
----

通过 hint 表，可以为特定查询自动应用 hints，无需修改 SQL 语句。

== IvorySQL 兼容性

=== Oracle 兼容模式

pg_hint_plan 在 PostgreSQL 和 Oracle 兼容模式下均可正常工作。hint 语法保持一致，并与 IvorySQL 特有的数据类型（VARCHAR2、NUMBER 等）兼容。

=== Oracle 模式示例

[literal]
----
-- 连接到 1521 端口（Oracle 模式）
postgres=# /*+
   IndexScan(employees emp_name_idx)
*/
SELECT * FROM employees WHERE last_name = 'SMITH';
----

在 Oracle 兼容模式下，hint 的使用方法与 PostgreSQL 模式完全相同，可以正常控制包含 IvorySQL 特有数据类型和语法的查询执行计划。
