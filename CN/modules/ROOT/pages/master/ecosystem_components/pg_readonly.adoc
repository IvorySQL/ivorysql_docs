= pg_readonly

== 概述
pg_readonly 是一个能够将所有 PostgreSQL 的数据库设为只读的插件。 

pg_readonly 没有特定的GUC参数，它依靠内存中的全局标志来管理只读状态，并提供了SQL函数来设置或者查询全局标志。 
这个全局标志是集群级别的，集群中的数据库要么全部是只读的，要么全部是可读可写的。

只读模式通过过滤SQL语句实现。
[literal]
----
允许不包含有写动作函数的SELECT语句；
DML (INSERT, UPDATE, DELETE) 和 DDL 语句包括 TRUNCATE 完全不允许；
DCL 语句 GRANT 与 REVOKE 也是禁止的；
----

== 安装

[TIP]
源码安装环境为 Ubuntu 24.04(x86_64)，环境中已经安装了IvorySQL，安装路径为/path-to/ivorysql

=== 源码安装

[literal]
----
# 从 https://github.com/pierreforstmann/pg_readonly/releases/tag/1.0.6 下载 1.0.6 的源码包 1.0.6.tar.gz
tar xvf 1.0.6.tar.gz
cd pg_readonly-1.0.6

# 编译安装
make PG_CONFIF=/path-to/ivorysql/bin/pg_config 
make PG_CONFIF=/path-to/ivorysql/bin/pg_config install
----

=== 在 Windows 上从源码构建

[TIP]
本节在 Windows 11 上验证，编译器为 Visual Studio 2022 Build Tools（MSVC 19.44）。IvorySQL 的 Windows 移植仍在审查中，验证使用的 IvorySQL 是 https://github.com/jiabin777on-hue/IvorySQL/tree/win/reference[Windows 测试基线] 的提交 `947b50e1`，即 master 加上尚未合并的 Windows 移植 PR（IvorySQL #2321、#2332、#2333、#2485、#2530、#2811、#3418、#3419、#3420、#3421）。

在 “Developer PowerShell for VS 2022” 中编译并安装 IvorySQL。需要 Git、Strawberry Perl、winflexbison 和 Meson（含 Ninja）在 `PATH` 中。验证时另外加了 `-Dcassert=true -Dtap_tests=enabled` 以运行测试。

[source,powershell]
----
git clone --branch win/reference https://github.com/jiabin777on-hue/IvorySQL.git
Set-Location IvorySQL
git checkout 947b50e1
meson setup build --prefix=C:\ivorysql -Dauto_features=disabled -Duuid=none
ninja -C build
meson install -C build
Set-Location ..
----

Windows 上没有 PGXS，可以用 MSVC 的 `cl` 和 `link` 直接编译插件，并链接 IvorySQL 安装目录中的 `postgres.lib`。克隆时设置 `core.autocrlf=false`，避免测试数据文件被转换为 CRLF。

[source,powershell]
----
$IVY = 'C:\ivorysql'
$INC = "$IVY\include\postgresql\server"
$CFLAGS = @("/nologo", "/c", "/O2", "/MD", "/utf-8", "/std:c11", "/DWIN32", "/DWINDOWS",
    "/D__WINDOWS__", "/D__WIN32__", "/D_CRT_SECURE_NO_DEPRECATE", "/D_CRT_NONSTDC_NO_DEPRECATE",
    "/I.", "/I$INC\port\win32_msvc", "/I$INC\port\win32", "/I$INC", "/I$IVY\include")
git clone -c core.autocrlf=false https://github.com/pierreforstmann/pg_readonly.git
Set-Location pg_readonly
git checkout 18cc73c9b161
cl @CFLAGS pg_readonly.c
link /nologo /DLL /OUT:pg_readonly.dll pg_readonly.obj "$IVY\lib\postgres.lib"
Copy-Item pg_readonly.dll "$IVY\lib\postgresql\"
Copy-Item pg_readonly.control, pg_readonly--*.sql "$IVY\share\postgresql\extension\"
----

验证的版本为 pg_readonly 1.0.6（提交 `18cc73c9b161`），源码不需要修改。

pg_readonly 需要预加载。IvorySQL 在 `ivorysql.conf` 中默认设置了 `shared_preload_libraries = 'gb18030_2022, liboracle_parser, ivorysql_ora'`，要把 pg_readonly **追加**到这个列表后面，例如 `shared_preload_libraries = 'gb18030_2022, liboracle_parser, ivorysql_ora, pg_readonly'`。如果只写 `'pg_readonly'`，会覆盖默认列表，Oracle 模式的连接会报 `liboracle_parser not found`。

验证结果：插件自带的回归测试 `test` 在 PG 模式下通过。在 Oracle 模式下（脚本中补上 `/` 后）结果与期望输出一致，只是错误上下文中的类型名显示为 `pg_catalog.int4`，匿名块显示为 PL/iSQL。插件自带的回归测试脚本按 PostgreSQL 的语法编写。Oracle 模式的 psql 要看到单独一行的 `/` 才会发送 `CREATE FUNCTION`（即使函数体用 `$$` 引用），所以要在 Oracle 模式下运行这些脚本，需要在每个 `CREATE FUNCTION` 语句后面加一行 `/`。

=== 配置预加载库
修改 data 目录中的 ivorysql.conf 文件，向 shared_preload_libraries 中追加 pg_readonly。
shared_preload_libraries = 'pg_readonly'

== 创建Extension并确认pg_readonly版本

psql 连接到数据库，执行如下命令：
[literal]
----
ivorysql=# CREATE EXTENSION pg_readonly;
CREATE EXTENSION

ivorysql=# SELECT * FROM pg_available_extensions WHERE name = 'pg_readonly';
    name     | default_version | installed_version | location |          comment           
-------------+-----------------+-------------------+----------+----------------------------
 pg_readonly | 1.0.6           | 1.0.6             | $system  | cluster database read only
(1 row)
----

== 使用

=== 检查单个函数

[literal]
----
-- 查询当前集群只读状态
select get_cluster_readonly();
 get_cluster_readonly 
----------------------
 f
(1 row)

-- 设置当前集群为只读
select set_cluster_readonly();
 set_cluster_readonly 
----------------------
 t
(1 row)

-- 只读的集群只允许 SELECT 语句
select * from t;
 x | y 
---+---
(0 rows)

update t set x=33 where y='abc';
ERROR:  cannot execute UPDATE in a read-only transaction

select 1 into tmp;
ERROR:  cannot execute UPDATE in a read-only transaction

create table tmp(c text);
ERROR:  cannot execute UPDATE in a read-only transaction
----

更多详细使用方法和高级特性，请参阅 https://github.com/pierreforstmann/pg_readonly 。
