= **功能概述**

IvorySQL通过 `DBMS_SESSION` 包过程、核心包缓存接口和PL/iSQL运行时清理函数，实现Oracle兼容的包状态重置。公开调用 `CALL DBMS_SESSION.RESET_PACKAGE()` 会清理当前会话中全部已初始化包的可变运行时状态，并把这些包设置为 `PLISQL_PACKAGE_NO_INIT`。包的编译结果继续保留，完整初始化流程在下次访问各包时延迟执行。

基本用法如下：

```sql
SET ivorysql.compatible_mode = oracle;

CALL DBMS_SESSION.RESET_PACKAGE();
```

本功能由提交 `2bd694fe3a1a3c950b1b95f4412e516d7e42fc7e` 引入。实现同时提供按OID重置单包的内部能力，但面向用户的 `DBMS_SESSION.RESET_PACKAGE` 只公开无参数的重置全部包过程。

== 实现原理

=== SQL包接口与C函数入口

`contrib/ivorysql_ora/src/builtin_packages/dbms_session/dbms_session--1.0.sql` 在 `SYS` 模式中定义C函数：

```sql
CREATE FUNCTION sys.ora_dbms_session_reset_package()
RETURNS VOID
AS 'MODULE_PATHNAME', 'ora_dbms_session_reset_package'
LANGUAGE C VOLATILE;
```

同一安装脚本在 `DBMS_SESSION` 包声明中加入无参数过程 `RESET_PACKAGE`，包体通过下列语句调用内部C函数：

```sql
PROCEDURE reset_package IS
BEGIN
    PERFORM sys.ora_dbms_session_reset_package();
END;
```

`contrib/ivorysql_ora/src/builtin_packages/dbms_session/dbms_session.c` 中的 `ora_dbms_session_reset_package` 调用核心函数 `ResetAllPackagesContext()`，然后返回SQL `VOID`。核心函数计算出的实际重置数量不会通过公共过程返回。

调用链如下：

```
CALL DBMS_SESSION.RESET_PACKAGE()
    -> DBMS_SESSION包体过程reset_package
    -> sys.ora_dbms_session_reset_package()
    -> ResetAllPackagesContext()
    -> ResetPackageContext(pkg_oid)
    -> plisql_package_reset_context(pkg_oid)
```

=== 核心包缓存接口

`src/include/utils/packagecache.h` 和 `src/backend/utils/cache/packagecache.c` 增加两个核心接口：

```c
extern bool ResetPackageContext(Oid pkg_oid);
extern int  ResetAllPackagesContext(void);
```

`ResetPackageContext` 用于请求PL/iSQL重置指定OID对应的包。成功清理一个具有运行时状态的包时返回 `true`；包尚未达到可重置的初始化状态时返回 `false`。如果PL/iSQL插件尚未装载，该函数也直接返回 `false`。

`ResetAllPackagesContext` 返回实际被重置的包数量。PL/iSQL尚不可用时返回 `-1`；插件已经装载但没有包需要重置时返回 `0`。公共 `DBMS_SESSION` 入口忽略这个内部返回值，因此上述数值只用于核心代码和测试接口。

=== 两阶段遍历全部包

包运行时对象保存在当前后端进程的 `PackageCache` 哈希表中。重置全部包时，`PackageCacheListItems()` 先遍历哈希表，把现有 `PackageCacheItem` 指针收集到临时列表；随后 `ResetAllPackagesContext()` 再遍历该列表，对每个包调用 `ResetPackageContext()`。

该过程分为两个阶段：

1. 只读取包缓存并收集待处理项；
2. 离开哈希表迭代器后逐项执行状态修改和运行时资源释放。

这种方式避免在保持哈希表顺序扫描状态时执行可能影响包运行时的操作。临时列表处理完成后使用 `list_free` 释放，包缓存项本身继续保留。

由于缓存属于单个数据库后端，这一遍历天然只作用于当前会话；它不会访问或修改其他会话中的包实例。没有进入当前会话包缓存的目录对象也不会被加载。

=== Rendezvous解耦核心与PL/iSQL

核心包缓存代码不能直接链接PL/iSQL实现。`src/include/funcapi.h` 中的 `PLiSQL_funcs_call` 函数表新增回调：

```c
bool (*package_reset_context)(Oid pkg_oid);
```

PL/iSQL加载时，`src/pl/plisql/src/pl_subproc_function.c` 把该回调注册为 `plisql_package_reset_context`。核心层的 `ResetPackageContext()` 先检查 `plisql_internal_funcs.isload`，再通过函数表调用PL/iSQL。

这种rendezvous机制保持了核心包缓存与过程语言模块之间的边界：核心层负责选择一个或全部缓存项，PL/iSQL负责解释包内部数据结构并释放语言运行时状态。

=== 单包状态检查

`plisql_package_reset_context()` 首先用包OID在当前会话包缓存中查找 `PackageCacheItem`。PL/iSQL已经装载但OID没有对应缓存项时报告错误：

```
could not find package with OID ...
```

取得 `PLiSQL_package` 后，函数根据包状态决定后续行为：

* 状态为 `PLISQL_PACKAGE_REBUILD` 或 `PLISQL_PACKAGE_REBUILD_INIT` 时报告 `existing state of packages has been discarded`。这与包正常访问路径的失效检查一致，防止通过重置绕过失效状态并继续使用旧编译结果。
* 状态不高于 `PLISQL_PACKAGE_NO_STATUS_INIT` 时没有需要释放的运行时状态，返回 `false`。
* 其余已初始化状态进入逐datum清理，并在完成后返回 `true`。

公开的重置全部包入口只会对当前缓存项调用该逻辑。测试扩展提供的无效OID和 `NULL` 行为属于内部接口测试，不是公共 `DBMS_SESSION.RESET_PACKAGE` 的参数语义。

=== 逐datum清理运行时状态

PL/iSQL包的全局datum位于 `source.datums` 数组中。重置函数从下标0遍历到 `last_globaldno`，按datum类型释放当前值：

[cols="1,3"]
|===
|datum类型 |清理方式

|`PLISQL_DTYPE_VAR`
|如果变量类型为 `REFCURSOROID` 且值非空，先调用 `plisql_close_package_cursorvar()` 关闭游标。常量跳过后续清理；可变变量释放所拥有的普通或扩展值，再把 `value` 清零、`isnull` 设为真并清除 `freeval`。

|`PLISQL_DTYPE_REC`
|对于非常量记录，如果存在扩展记录头 `erh`，调用 `DeleteExpandedObject()` 释放并将指针置空。

|`PLISQL_DTYPE_ROW`
|行变量的实际值保存在其引用的 `VAR` 或 `REC` datum中，不需要重复释放。

|`PLISQL_DTYPE_RECFIELD`、`PROMISE`、`PACKAGE_DATUM`、`EXCEPTION`
|这些datum本身没有由包持有的堆分配值，不执行资源释放。
|===

普通数组、可变长度值等可能使用PostgreSQL扩展对象表示。实现通过 `DatumIsReadWriteExpandedObject()` 区分扩展对象与普通指针，分别调用 `DeleteExpandedObject()` 或 `pfree()`，避免只把变量置空而泄漏内存。

=== 保留编译结果而不重置整个内存上下文

实现没有直接调用 `MemoryContextReset(item->ctxt)`。当前包内存上下文同时保存两类对象：

* 包的编译结构，包括 `PLiSQL_package`、datum数组、已解析语句和类型信息；
* 包变量当前持有的运行时值。

重置整个上下文会连同编译结果一起销毁，并迫使下次访问重新编译包。逐datum释放只丢弃运行时值，使缓存的编译形式可以继续使用，降低重置后的恢复成本。

当前代码通过类型分支精确管理这两类对象。若以后为包状态建立独立运行时内存上下文，才可能把运行时清理改为直接重置该独立上下文。

=== NO_INIT状态与延迟初始化

运行时值清理完成后，函数执行：

```c
psource->status = PLISQL_PACKAGE_NO_INIT;
```

`PLISQL_PACKAGE_NO_INIT` 表示包的编译形式仍然有效，但当前会话实例尚未初始化。下一次解析包datum或调用包子程序时，现有包状态检查路径调用 `plisql_exec_package_init()`，执行完整的初始化流程：

1. 计算包变量的声明默认表达式；
2. 为没有默认表达式的变量建立空值状态；
3. 执行包体初始化部分；
4. 把包状态恢复为已初始化状态。

因此，重置使用的是“清理后延迟重新实例化”，而不是在调用时保存并恢复一份初始值快照。`SYSDATE`、序列 `NEXTVAL` 和跨包函数调用等动态表达式会在首次重新访问时求值，包初始化部分也在该时刻重新执行。

逐包延迟初始化还意味着 `ResetAllPackagesContext()` 不会在重置过程中触发包之间的初始化依赖。重置后的包按应用程序后续访问顺序分别初始化。

=== 非包会话状态隔离

应用上下文由 `DBMS_SESSION.SET_CONTEXT` 使用独立的会话状态保存，不位于PL/iSQL包datum或包缓存运行时值中。重置路径只遍历 `PackageCache` 并清理各包的全局datum，因此不会清除 `SYS_CONTEXT` 可见的应用上下文。

这也是 `RESET_PACKAGE` 与 `DISCARD ALL` 的重要区别：前者针对包实例，后者可清理更广泛的连接级状态。

=== 测试覆盖

公共 `DBMS_SESSION` 回归用例位于：

```
contrib/ivorysql_ora/sql/dbms_session.sql
contrib/ivorysql_ora/expected/dbms_session.out
```

测试覆盖没有已初始化用户包时的空操作、修改包变量后恢复默认值，以及重置包后应用上下文继续保留。

专用内部测试模块位于：

```
src/oracle_test/modules/test_package_reset/
```

该模块通过rendezvous接口提供测试专用的 `reset_package_by_oid(oid)` 和 `reset_all_packages()` SQL包装，覆盖以下实现行为：

* 按OID重置一个包且不影响同一会话中的其他包；
* 重置全部已初始化包并统计实际重置数量；
* 恢复数值和文本默认值，以及无默认值变量的 `NULL` 状态；
* 释放数组等扩展对象；
* 无效OID、空参数和PL/iSQL尚未装载时的内部返回行为。

测试扩展仅用于验证核心接口，不构成面向应用程序的兼容API。
