= Docker & Podman 部署IvorySQL

[TIP]
====
除 Docker Hub 外，IvorySQL 社区还为国内用户提供 Harbor 镜像服务。将本章节中的镜像地址前缀替换为 `registry.highgo.com/` 即可使用，例如 `registry.highgo.com/ivorysql/ivorysql:5.6-ubi8`。
====

== 镜像与监听端口

官方镜像 `ivorysql/ivorysql` 以 `5.6-ubi8` 为主标签，另有 `5.6-bookworm`、`5.6-trixie` 等基于不同基础镜像的变体，功能一致。镜像默认声明三个端口：

[cols="1,1,3"]
|===
| 端口 | 用途 | 说明

| `5432/tcp` | PostgreSQL 兼容监听 | 从该端口连入的会话，`ivorysql.compatible_mode` 为 `pg`
| `1521/tcp` | Oracle 兼容监听 | 从该端口连入的会话，`ivorysql.compatible_mode` 为 `oracle`
| `5866/tcp` | 初始化临时端口 | 只在容器初始化阶段内部使用，**不是对外服务**，无需发布
|===

数据目录由镜像环境变量 `PGDATA` 固定为 `/var/local/ivorysql/ivorysql-5/data`，并声明为匿名卷。生产环境建议改用命名卷，见下文「数据持久化」。

== docker 方式运行

=== 拉取镜像

[source,bash]
----
$ docker pull ivorysql/ivorysql:5.6-ubi8
----

=== 启动容器

`IVORYSQL_PASSWORD` 是**必需**变量，它决定初始化时创建的超级用户口令。缺省时容器会直接退出（退出码 `1`），并在日志里给出：

[source,text]
----
Error: Database is uninitialized and superuser password is not specified.
       You must specify IVORYSQL_PASSWORD to a non-empty value for the
       superuser. For example, "-e IVORYSQL_PASSWORD=password" on "docker run".

       You may also use "POSTGRES_HOST_AUTH_METHOD=trust" to allow all
       connections without a password. This is *not* recommended.
----

下面这条命令同时做了四件事：指定口令、把数据目录挂到命名卷、发布两个监听端口、加上健康检查：

[source,bash]
----
$ docker run -d --name ivorysql \
    -e IVORYSQL_PASSWORD=your_password \
    -v ivorysql_data:/var/local/ivorysql/ivorysql-5/data \
    -p 1521:1521 -p 5433:5432 \
    --health-cmd "pg_isready -p 1521 -U ivorysql" \
    --health-interval 10s --health-timeout 5s --health-retries 5 \
    ivorysql/ivorysql:5.6-ubi8
----

这里把容器的 `1521` 原样发布到宿主机 `1521`，把容器的 `5432` 发布到宿主机 `5433`，避免与本机已有的 PostgreSQL 冲突。宿主机端口可以按需调整。

[source,bash]
----
$ docker port ivorysql

1521/tcp -> [::]:11521
5432/tcp -> 0.0.0.0:15532

----

（上面的输出取自把容器端口发布到 `11521`、`15532` 的一次实测；按上一节的命令，这里应显示 `1521` 与 `5433`。）

=== 环境变量

[cols="1,1,3"]
|===
| 变量 | 默认值 | 说明

| `IVORYSQL_PASSWORD` | 无（必需） | 超级用户口令，缺失时容器退出
| `IVORYSQL_USER` | `ivorysql` | 初始化时创建的超级用户名
| `IVORYSQL_DB` | 与 `IVORYSQL_USER` 相同 | 初始化时创建的数据库名
| `POSTGRES_INITDB_ARGS` | 无 | 追加给 `initdb` 的参数，例如 `-m pg` 可改成 PostgreSQL 模式初始化
| `POSTGRES_HOST_AUTH_METHOD` | 无 | 设为 `trust` 可免密，容器会打印风险警告，不建议在生产使用
|===

首次初始化时，挂载到 `/docker-entrypoint-initdb.d/` 下的 `*.sql` 会被自动执行，可用于建库建表或装载种子数据。

=== 数据持久化

容器把数据写在 `PGDATA`（`/var/local/ivorysql/ivorysql-5/data`）里，不挂卷时容器删除即丢数据。改用命名卷后，重启与重建容器都不影响数据：

[source,bash]
----
$ docker restart ivorysql
$ psql -h 127.0.0.1 -p 1521 -U ivorysql -d postgres -c "select id, note from t_vol;"
 id | note
----+------
  1 | ok
(1 row)
----

卷在宿主机上的真实位置可以用 `docker volume inspect` 查看：

[source,bash]
----
$ docker volume inspect ivorysql_data
"Mountpoint": "/var/lib/docker/volumes/ivorysql_data/_data",
"Driver": "local",
----

挂载成功后，`PGDATA` 目录内可见 `PG_VERSION`（内容为 `18`）、`ivorysql.conf`、`pg_hba.conf` 等文件。

=== 健康检查

镜像里**没有** `ss`、`netstat`、`ps`（执行 `ps` 会得到 `ps: command not found`），所以健康检查不要依赖 `ss -lntp` 或 `curl`，用镜像自带的 `pg_isready` 即可，两个端口都能探测：

[source,text]
----
/var/local/ivorysql/ivorysql-5/bin/pg_isready -p 5432   →  /tmp:5432 - accepting connections   rc=0
/var/local/ivorysql/ivorysql-5/bin/pg_isready -p 1521   →  /tmp:1521 - accepting connections   rc=0
----

== 一个容器，两个端口，两种兼容模式

这是 IvorySQL 镜像最容易踩坑的地方：**同一个容器、同一份数据，从 `1521` 连进去是 Oracle 兼容模式，从 `5432` 连进去是 PostgreSQL 模式**。

[source,bash]
----
$ psql -h 127.0.0.1 -p 5433 -U ivorysql -d postgres -At \
    -c "select current_setting('ivorysql.port') as ivory, current_setting('ivorysql.compatible_mode') as mode, current_setting('server_version') as ver"
1521|pg|18.6

$ psql -h 127.0.0.1 -p 1521 -U ivorysql -d postgres -At -c "<同一条查询>"
1521|oracle|18.6
----

对比 `pg_settings` 里的 `ivorysql.*` 参数，两侧八项中**只有 `ivorysql.compatible_mode` 不同**：

[source,text]
----
# 1521 监听
ivorysql.compatible_mode=oracle
ivorysql.database_mode=oracle
ivorysql.datetime_ignore_nls_mask=0
ivorysql.enable_case_switch=on
ivorysql.enable_emptystring_to_NULL=on
ivorysql.identifier_case_switch=interchange
ivorysql.listen_addresses=*
ivorysql.port=1521

# 5432 监听
ivorysql.compatible_mode=pg
（其余 7 项完全相同）
----

注意 `ivorysql.database_mode` 在两种连接下都是 `oracle`：它记录的是建库时选择的模式，不会因为换了连接端口而改变；改变的是当前会话按哪套语义解析 SQL。

因此在 Oracle 监听上可以直接建 Oracle 风格的表，建好后两个端口都能读：

[source,sql]
----
create table if not exists t_vol(id int primary key, note varchar2(20));
insert into t_vol values (1, 'ok');

select id, note from t_vol;
 id | note
----+------
  1 | ok
(1 row)
----

容器默认按 Oracle 模式初始化，这是 `initdb` 自身的默认值（`-m, --dbmode=MODE  set database mode, default is oracle`）；启动脚本没有另外传参，所以想改成 PostgreSQL 模式初始化，需要用 `-e POSTGRES_INITDB_ARGS="-m pg"`。

== podman 方式运行

Podman 的命令行与 Docker 基本一致，把上文的 `docker` 换成 `podman` 即可：

[source,bash]
----
$ podman pull ivorysql/ivorysql:5.6-ubi8
$ podman run -d --name ivorysql \
    -e IVORYSQL_PASSWORD=your_password \
    -v ivorysql_data:/var/local/ivorysql/ivorysql-5/data \
    -p 1521:1521 -p 5433:5432 \
    ivorysql/ivorysql:5.6-ubi8
$ podman ps --filter name=ivorysql
----

容器起来后用 `podman exec` 进入容器，或在宿主机上直接用 `psql` 连两个端口，验证方式与 Docker 完全相同：

[source,bash]
----
$ podman exec -it ivorysql psql -U ivorysql -d postgres -c "select version();"
$ psql -h 127.0.0.1 -p 1521 -U ivorysql -d postgres     # Oracle 兼容
$ psql -h 127.0.0.1 -p 5433 -U ivorysql -d postgres     # PostgreSQL 兼容
----

== 常见问题

* **容器起来就退出**：`docker logs ivorysql` 里出现 `Database is uninitialized and superuser password is not specified.`，说明漏了 `-e IVORYSQL_PASSWORD`。
* **`1521` 连不上**：`docker ps` 的 `PORTS` 列里只有 `5432/tcp`，说明启动时没发布 `1521`，补上 `-p 1521:1521`。
* **宿主机 `1521` 已被占用**：改发布端口即可，例如 `-p 11521:1521`，容器内仍是 `1521`。
* **看到 `5866/tcp` 却连不上**：它是初始化阶段的临时端口，只在容器初始化时于本机使用，不对外提供服务。
